# Hey Jarvis — Voice-Controlled YouTube Music Assistant

An end-to-end NLP & speech-controlled YouTube Music assistant built with Python (3.11 or 3.12) and Streamlit. It combines wake-word detection, local speech-to-text, side-by-side intent classification (**TF-IDF + Logistic Regression** vs. **Fine-Tuned DistilBERT**), and an embedded in-app YouTube player.

---

## What It Can Do

- **Wake-Word Detection (`openWakeWord`)**: Listens for `"Hey Jarvis"` in real time (`16 kHz` mono PCM via `PyAudio`, ONNX inference) and captures a configurable command window (`2.5s–6.0s`).
- **Local Speech-to-Text (`faster-whisper`)**: Transcribes recorded voice commands locally using `base.en` (`int8`) with VAD filtering.
- **Side-by-Side Intent Classification**: Runs both a classical baseline (`TF-IDF + Logistic Regression`) and a transformer (`distilbert-base-uncased`) on every command, displaying predicted intent, confidence, and inference latency (ms).
- **8 Supported Intents & In-App Player Controls**:
  - `PlayMusic` — Extracts the song/artist query, searches YouTube Music via `ytmusicapi`, loads the top 5 matches into the queue, and plays the top track inside the embedded Streamlit YouTube IFrame Player.
  - `AddToPlaylist` — Searches YouTube Music for the matching track and adds it to the in-app playlist and queue.
  - `PauseMusic` — Pauses the in-app YouTube player.
  - `ResumeMusic` — Resumes playback in the in-app YouTube player.
  - `NextTrack` / `PreviousTrack` — Cycles forward/backward through the loaded track queue.
  - `VolumeControl` — Raises/lowers volume in `20%` steps (`0–100%`) or mutes/unmutes the in-app player.
  - `OutOfScope` — Safely ignores non-music or non-playback queries (e.g., weather, restaurant booking, *"find the song..."*).
- **Text Sandbox Mode**: Test intent classification, query extraction, and player controls without a microphone.

## Model Benchmark (`data/processed/test.csv`, 731 samples)

Dataset: Merged Snips NLU (`PlayMusic`, `AddToPlaylist`, and 5 other intents mapped to `OutOfScope`) + custom playback commands (`60+` per playback class) across `13,324` train / `730` val / `731` test rows.

| Metric | TF-IDF + LogisticRegression | Fine-Tuned DistilBERT |
| :--- | :---: | :---: |
| **Accuracy** | `0.9891` | `0.9932` |
| **Macro F1** | `0.9639` | `0.9584` |
| **Weighted F1** | `0.9889` | `0.9932` |
| **`PlayMusic` <-> `OutOfScope` Confusions** | `4` | `1` |
| **Avg Single-Query Latency (ms), laptop CPU** | `0.186` | `14.719` |

Latency was measured on an Apple Silicon laptop CPU. An earlier run on an NVIDIA GPU (CUDA) measured DistilBERT at about `3.3 ms`, so the transformer's cost depends heavily on hardware, while the TF-IDF model stays under `0.3 ms` either way.

**Reading these numbers:** DistilBERT is more accurate overall, but the TF-IDF model has a slightly higher macro F1. Macro F1 weights all 8 classes equally, and the playback classes (`PauseMusic`, `ResumeMusic`, `NextTrack`, `PreviousTrack`, `VolumeControl`) have only 6–7 test examples each, so a single wrong prediction moves that class's precision or recall by roughly 15 points. Small re-training differences shift macro F1 noticeably for the same reason; an earlier run measured `0.9740` (TF-IDF) and `0.9845` (DistilBERT).

## Text Preprocessing

### Statistical model (TF-IDF + Logistic Regression)

1. **Label mapping** (`nlp/dataset_builder.py`): Snips intents other than `PlayMusic` and `AddToPlaylist` are relabeled `OutOfScope`. Snips has no playback-control intents, so those come from `data/custom_playback.csv`, generated by `nlp/generate_custom_data.py`.
2. **Normalization:** case folding (lowercase) and trimming whitespace, applied to every row when the dataset is built and again to each command at prediction time (`nlp/predictor.py`).
3. **Tokenization:** scikit-learn's default regex tokenizer, `(?u)\b\w\w+\b`, keeps runs of 2+ word characters, so punctuation is removed and single characters are dropped as part of tokenization.
4. **Features:** TF-IDF over unigrams and bigrams (`ngram_range=(1, 2)`), capped at the 10,000 most frequent terms. Bigrams keep short phrases such as "go back", "skip this" and "turn it" together as single features, adding some word-order information that single words lack.
5. **Class imbalance:** `LogisticRegression(class_weight="balanced")` so the small playback classes are not drowned out by the 500-row `OutOfScope` class.

**Deliberately not used:**
- **Stop-word removal.** Standard English stop-word lists remove words such as "up", "down", "off", "next" and "back", which are exactly the words that separate one playback command from another.
- **Stemming and lemmatization.** Commands are short and use a small, fixed vocabulary, so merging word forms gives little benefit, and bigrams already capture the useful phrases.

### Transformer (DistilBERT)

DistilBERT handles its own preprocessing through its pretrained tokenizer (`AutoTokenizer` for `distilbert-base-uncased`):

- **WordPiece sub-word tokenization**, so unseen song or artist names are split into known pieces instead of becoming unknown tokens (for example, "play Kodak Black ZEZE" → `play`, `ko`, `##dak`, `black`, `ze`, `##ze`).
- **Lowercasing** is built into the uncased model.
- **Special tokens** `[CLS]` and `[SEP]` are added, and the `[CLS]` output is used for classification.
- **Truncation** to `32` tokens (voice commands are short) and **dynamic padding** per batch (`DataCollatorWithPadding`).
- Training: `3e-5` learning rate, batch size `32`, `4` epochs, keeping the checkpoint with the best validation macro F1.

### Query extraction (information extraction)

For `PlayMusic` and `AddToPlaylist`, `extract_music_query()` in `nlp/predictor.py` uses regular expressions to strip wrappers such as "hey jarvis", "can you", "play" and "on youtube music" / "to my playlist", leaving the song or artist to search for ("can you play blinding lights please" → "blinding lights").

## Getting Started

Run every command from the project root folder. Tested with Python 3.11 and 3.12.

1. **Install PortAudio (macOS / Linux only)**. `PyAudio` needs it to build. Windows users can skip this step.
   ```bash
   # macOS
   brew install portaudio
   # Ubuntu / Debian
   sudo apt-get install portaudio19-dev
   ```
2. **Create an environment and install dependencies** (any virtual environment or conda environment works):
   ```bash
   python -m venv .venv
   source .venv/bin/activate        # Windows PowerShell: .venv\Scripts\Activate.ps1
   pip install -r requirements.txt
   ```
3. **Train the models (required on first setup)**. The trained weights are too large for GitHub, so `models/` only contains the benchmark report until you train. The processed dataset is already in `data/processed/`, so two scripts are enough:
   ```bash
   python nlp/train_baseline.py      # seconds
   python nlp/train_transformer.py   # a few minutes on a laptop, faster on a GPU
   python nlp/evaluate_compare.py    # optional: refreshes models/comparison_report.json
   ```
   To rebuild the dataset from scratch first (downloads Snips from Hugging Face), run `python nlp/generate_custom_data.py` and `python nlp/dataset_builder.py` before the training scripts. [notebooks/train_models.ipynb](notebooks/train_models.ipynb) runs the whole sequence.
4. **Launch the Streamlit app**. Use `streamlit run`, not `python app.py`, which exits without opening the UI:
   ```bash
   streamlit run app.py
   ```
   The app opens at `http://localhost:8501`. The first time, Streamlit asks for an optional email address (press Enter to skip) and your OS asks for microphone access. On first use the wake-word model and the Whisper model download automatically, and YouTube playback needs an internet connection.

## Ideas for Groupmates to Improve

- **Authenticated YouTube Music Playlists**: Connect `ytmusicapi` OAuth/browser headers so `AddToPlaylist` saves songs to a real YouTube Music account playlist instead of only the in-app session playlist.
- **Hands-Free Continuous Listening**: Add an always-on background listener mode in `app.py` (using `streamlit` threading/polling or WebRTC) so users don't have to click the listen button for each command.
- **Entity / Slot Extraction (NER)**: Replace regex-based `extract_music_query()` with a sequence-labeling / NER model to separately extract `song`, `artist`, `playlist_name`, and `volume_level` (e.g., *"set volume to 35%"*).
- **Automated Playback Progression**: Hook the YouTube IFrame `onStateChange` (`YT.PlayerState.ENDED`) event to automatically advance to the next track in the queue.
- **Expanded Evaluation & Unit Tests**: Add a `tests/` suite with `pytest` covering edge cases, noisy ASR transcripts, and out-of-scope adversarial queries.
